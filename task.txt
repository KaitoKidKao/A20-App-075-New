**Mục Tiêu**
Đưa dự án từ MVP/demo lên mức production ổn định cho ứng dụng giáo dục hỗ trợ người khiếm thính. Ưu tiên theo thứ tự: dữ liệu đúng, pipeline xử lý ổn định, bảo mật, accessibility, khả năng mở rộng, rồi mới đến các tính năng nâng cao.

**Phase 1: Ổn Định Nền Tảng Backend**
Mục tiêu: backend chạy ổn định, dữ liệu không mất, job không kẹt.

Tasks:
- Chuẩn hóa `DATABASE_URL` production bằng PostgreSQL, giữ SQLite chỉ cho local.
- Hoàn thiện Alembic migration, đảm bảo `alembic upgrade head` chạy sạch trên DB mới.
- Tách rõ model dữ liệu chính: `User`, `Lesson/Video`, `LectureContent`, `ProcessingJob`, `TranscriptSegment`, `Flashcard`, `Quiz`, `Progress`.
- Thêm endpoint `POST /api/videos/{id}/reprocess` để xử lý lại video lỗi mà không cần upload lại.
- Chuẩn hóa job status: `queued`, `extracting_audio`, `transcribing`, `translating`, `ai_processing`, `completed`, `failed`.
- Thêm retry cho job queue và lưu `error_message`, `attempts`, `last_failed_at`.
- Đưa file video/audio/transcript/avatar ra object storage như S3, R2 hoặc MinIO.

Tiêu chí hoàn thành:
- Upload video không mất trạng thái khi restart server.
- Worker chết có thể chạy lại job hoặc đánh dấu lỗi rõ ràng.
- Có thể reprocess video đã upload.

**Phase 2: Pipeline Caption Song Ngữ Chuẩn**
Mục tiêu: transcript Anh/Việt tách biệt, timeline đúng, không bị trộn ngôn ngữ.

Tasks:
- Lấy transcript gốc từ Whisper làm `source_language`.
- Lưu `segments_by_language[source_language]` là bản gốc.
- Dịch sang ngôn ngữ còn lại bằng JSON strict theo `index/start/end/text`.
- Không overwrite transcript gốc.
- Nếu dịch lỗi batch, retry batch nhỏ hơn.
- Nếu vẫn lỗi, lưu trạng thái `translation_failed` nhưng vẫn hiển thị caption gốc.
- Thêm test cho video tiếng Anh và tiếng Việt:
  - EN input tạo đủ `en` + `vi`.
  - VI input tạo đủ `vi` + `en`.
  - `start/end` của bản dịch khớp bản gốc.
- Thêm UI hiển thị rõ `VI` / `EN`, không fallback trộn dữ liệu.

Tiêu chí hoàn thành:
- Người dùng chọn `VI` xem đầy đủ tiếng Việt.
- Người dùng chọn `EN` xem đầy đủ tiếng Anh.
- Timeline caption không lệch giữa hai ngôn ngữ.

**Phase 3: Bảo Mật Và Auth Production**
Mục tiêu: bảo vệ tài khoản, token, dữ liệu học tập và file media.

Tasks:
- Dùng HttpOnly cookie cho access token, không lưu token nhạy cảm trong localStorage.
- Cấu hình `AUTH_COOKIE_SECURE=true` ở production.
- Thêm refresh token hoặc session rotation nếu cần phiên đăng nhập dài.
- Thêm RBAC rõ ràng: `student`, `teacher`, `admin`.
- Kiểm tra quyền truy cập từng video/lesson theo owner/enrollment.
- Thêm rate limit cho login, upload, generate avatar.
- Validate file upload: MIME type, extension, size, duration.
- Thêm scan cơ bản cho file upload nếu triển khai công khai.
- Không commit `.env`, không log API key/token.

Tiêu chí hoàn thành:
- User không xem được video của người khác.
- Cookie auth an toàn ở production.
- Upload độc hại bị chặn sớm.

**Phase 4: Frontend Học Tập Và Accessibility**
Mục tiêu: giao diện dễ dùng cho người khiếm thính, đạt gần WCAG 2.2 AA.

Tasks:
- Hoàn thiện video lesson page:
  - caption song ngữ
  - panel transcript đồng bộ
  - click transcript để tua video
  - progress học tập tự lưu
- Thêm tùy chọn caption:
  - bật/tắt nền caption
  - cỡ chữ
  - vị trí caption
  - line height
  - chọn `VI`/`EN`
- Thêm keyboard navigation:
  - play/pause
  - tua 5s/10s
  - đổi phụ đề
  - focus transcript hiện tại
- Thêm chế độ reduced motion.
- Kiểm tra contrast, focus ring, aria-label, semantic button/tab.
- Chạy Lighthouse + axe DevTools.
- Test UI mobile: video, caption, panel transcript không overlap.

Tiêu chí hoàn thành:
- Dùng app được bằng bàn phím.
- Caption đọc rõ trên mobile và desktop.
- Không có lỗi accessibility nghiêm trọng.

**Phase 5: Nội Dung Học Tập Và AI Artifacts**
Mục tiêu: biến video thành bài học có giá trị, không chỉ là phụ đề.

Tasks:
- Chuẩn hóa output AI:
  - summary
  - timeline
  - highlights
  - questions
  - briefing
  - flashcards
  - quizzes
  - visual data
- Dùng schema JSON rõ ràng cho từng artifact.
- Nếu AI trả sai schema, retry hoặc fallback.
- Thêm trạng thái sẵn sàng riêng cho từng artifact.
- Thêm màn hình review nội dung cho teacher/admin.
- Cho phép chỉnh transcript, flashcard, quiz trước khi publish.
- Gắn artifact vào ngôn ngữ chính, ưu tiên tiếng Việt cho học sinh Việt Nam.

Tiêu chí hoàn thành:
- Video xử lý xong tạo được bài học đầy đủ.
- Artifact lỗi không làm hỏng toàn bộ bài học.
- Giáo viên có thể sửa nội dung trước khi dùng thật.

**Phase 6: Avatar Và Ngôn Ngữ Ký Hiệu**
Mục tiêu: tính năng ký hiệu hữu ích, không chỉ mang tính minh họa.

Tasks:
- Tách rõ `caption`, `VSL gloss`, `avatar video`.
- Lưu gloss theo timeline.
- Thêm trạng thái generate avatar riêng.
- Cache avatar đã sinh.
- Cho phép tải manifest render.
- Thêm review thủ công gloss trước khi sinh avatar.
- Làm việc với người dùng khiếm thính/giáo viên chuyên biệt để kiểm chứng độ đúng của ký hiệu.
- Nếu avatar chưa đủ chính xác, gắn nhãn rõ là “hỗ trợ trực quan”, không thay thế thông dịch viên ký hiệu.

Tiêu chí hoàn thành:
- Avatar không block việc xem bài học.
- Gloss có thể review/chỉnh sửa.
- Người dùng hiểu giới hạn của avatar AI.

**Phase 7: Theo Dõi Tiến Độ Học Tập**
Mục tiêu: app trở thành nền tảng học, không chỉ công cụ xử lý video.

Tasks:
- Lưu thời lượng đã xem.
- Lưu phần trăm hoàn thành.
- Lưu flashcard đã học/chưa học.
- Lưu quiz score.
- Dashboard student:
  - khóa đang học
  - bài chưa hoàn thành
  - điểm quiz
  - hoạt động gần đây
- Dashboard teacher/admin:
  - số học sinh học
  - video xử lý lỗi
  - bài học phổ biến
  - tỷ lệ hoàn thành.

Tiêu chí hoàn thành:
- Student quay lại học tiếp đúng vị trí.
- Teacher biết học sinh đang tiến bộ hay gặp khó.

**Phase 8: DevOps, CI/CD Và Observability**
Mục tiêu: deploy được, debug được, rollback được.

Tasks:
- Hoàn thiện GitHub Actions:
  - install deps
  - lint frontend
  - typecheck frontend
  - backend tests
  - alembic migration check
  - build frontend
- Docker hóa backend, frontend, worker.
- Tạo `docker-compose` cho local production-like:
  - backend
  - frontend
  - PostgreSQL
  - Redis
  - worker
  - MinIO nếu dùng object storage local
- Thêm structured logging.
- Thêm monitoring:
  - job duration
  - failed jobs
  - upload count
  - AI cost estimate
  - queue length
- Thêm healthcheck:
  - API
  - DB
  - Redis
  - worker heartbeat.

Tiêu chí hoàn thành:
- Deploy lại được từ repo.
- Lỗi job có log và nguyên nhân rõ.
- CI chặn code làm vỡ build.

**Phase 9: QA Và Kiểm Thử Người Dùng**
Mục tiêu: đảm bảo sản phẩm đúng với người dùng mục tiêu.

Tasks:
- Test end-to-end:
  - register/login
  - upload video
  - wait processing
  - view bilingual caption
  - use transcript
  - complete lesson
- Test accessibility thủ công với keyboard-only.
- Test screen reader cơ bản.
- Test mobile viewport.
- Test video dài và file lớn.
- Test mất Redis, mất OpenAI, worker restart.
- Mời 3-5 người dùng khiếm thính hoặc giáo viên hỗ trợ đặc biệt dùng thử.
- Ghi nhận vấn đề về caption, tốc độ đọc, ký hiệu, bố cục.

Tiêu chí hoàn thành:
- Có checklist QA pass trước release.
- Có feedback thật từ nhóm người dùng mục tiêu.
- Các lỗi blocker được fix trước production.

**Ưu Tiên Triển Khai**
1. Hoàn thiện `Phase 1` và `Phase 2` trước: dữ liệu, job, caption song ngữ là lõi sản phẩm.
2. Làm `Phase 3` trước khi public internet: auth và quyền truy cập không được để sau.
3. Làm `Phase 4` song song với test người dùng: accessibility là yêu cầu sản phẩm, không phải polish.
4. Sau đó mới mở rộng `Phase 5`, `Phase 6`, `Phase 7`.
5. `Phase 8` và `Phase 9` cần bắt đầu sớm nhưng có thể hoàn thiện dần trước release.

Khuyến nghị mốc thực tế:
- Tuần 1: backend data/job/reprocess + caption song ngữ.
- Tuần 2: auth/security + frontend accessibility caption.
- Tuần 3: AI artifact schema + progress tracking.
- Tuần 4: Docker/CI/CD + QA người dùng + hardening production.
